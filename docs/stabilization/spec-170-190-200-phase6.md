## Security and scholarly guarantees

- No source-manuscript editing locks. Existing target translations and
  translator notes remain intact through explicit resynchronization.
- Account/role labels and mere review assignment names do not create new
  permissions or publication approval. Server-side authorization remains
  the authoritative gate.
- Author projections never include `editor_only` feedback or unrelated-round
  comments. Reviewer and editor projections are copies, not writable access
  to the retained domain objects.
- The review domain projection is **not itself a server authorization boundary**.
  Routes and editorial release workflow must independently check the
  authorized recipient, assignment, manuscript and round. A review's
  `author_and_editor` flag alone does not constitute final editorial release.
- Confidential author data and reviewer identities must still be tested
  across exports, revision snapshots, notifications, shared sessions
  and connected OJS/OMP journal authority.
- No user-uploaded manuscript, reviewer private feedback, real invitation
  tokens or account identifiers are committed as test fixtures.

## Approval gates

1. All mandatory test, typecheck, security, database, iOS and release
   readiness checks must pass on this exact head SHA.
2. Confirm phase 4 #790 and phase 5 #791 have passed review and have no
   outstanding red or unresolved required checks.
3. Verify manual double-blind and single-blind review boundaries, simulated
   revocation during collaboration, foreign-scope authorization and
   non-destructive translation synchronization.
4. Audit status remains **Draft** for all three normative models. Green Studio
   tests prove only the behavior represented by the tests.
5. **Do not increase the Studio version** until all nine stabilization stages
   have passed their relevant gates and the user approves the unified release.
