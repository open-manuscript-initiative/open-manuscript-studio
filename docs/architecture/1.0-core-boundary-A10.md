# Studio 1.0 architectural dependency boundary — A10 (incremental)

**Status:** Phase A boundary enforcement proposal. Not an overall architecture freeze, portable AST migration, release approval, or specification conformance claim.

The [OMI Studio 1.0 refactoring plan](https://openmanuscript.org/docs/governance/studio-1.0-architecture/refactoring-pr-plan/) requires core implementation dependencies to flow outward through explicit application/platform ports instead of silently importing UI/runtime modules. The existing Studio has substantial model and editor functionality; wholesale relocation could break manuscript editing, deletion, versioning and export.

## Enforced increment

`scripts/check-core-import-boundaries.mjs` uses the repository's TypeScript parser to scan **every tracked `src/model/**/*.ts(x)` file**. Normal value imports, reexports, `import = require`, `require(...)` and literal dynamic `import(...)` fail CI when the semantic model directly imports:

- React or React DOM, Zustand, Tauri native APIs, Prisma client or Express;
- project UI/editor/application/store/platform runtimes (`src/components`, `src/editor`, `src/app`, `src/store`, `src/platform`);
- project network/service implementation modules (`src/services`).

TypeScript type-only imports, including `import { type X }`, are permitted temporarily as erased interface dependencies; they do not execute services in the semantic-model runtime. A model importing its own model/types/document modules remains allowed.

Regression fixtures ensure that forbidden imports and dynamic/native imports fail and type-only dependencies stay legal. The gate runs in **regular Studio CI** and in **1.0 Readiness**. It checks no user content, metadata or secret values.

## Boundaries not yet claimed

- This protects the current `src/model` entrypoint only; `src/document`, `src/types`, import/export services, the full TypeScript dependency graph and backend Prisma/HTTP route/service isolation require an incremental contract survey before strengthening enforcement.
- Existing `src/model/translation.ts` imports `../integrations/structuredExternalContent.ts` at runtime. The gate does **not** forbid `src/integrations` yet. Extract the pure translation-plan data operation into a model or an application-owned port first, characterize its behavior, then extend the rule. Do not silently block the working translation feature.
- A future `ContentCodec`, unified `StudioApplication` façade, `RevisionRepository`, `SecureStorage` and portable OMI AST remain separate **A06/B01/B05/B06/B07/B10** work. This PR does not freeze any schema/format or remove compatibility facades.
- Regex/AST scan sees static module specifiers; calculated runtime URLs, injected scripts, package transitive dependencies and network policies are handled by other security gates and code review.

## Verify

```bash
npm ci
npm run check:core-boundaries
npm run lint
npm run build
```

CI failure should be fixed by moving a behavior into its proper application/platform adapter or introducing a pure interface rather than weakening the gate or deleting author functionality.

**Rollback:** remove the gate script/test and its two workflow calls if a false positive blocks builds, without changing any manuscript data or application runtime. The source remains executable before and after; no database migration, app version bump or native rebuild is needed.
