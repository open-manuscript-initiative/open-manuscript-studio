# ADR-030 — Session, integration, container and RC evidence boundaries

Status: proposed repair, 2026-11-01. Companion OMI governance documents remain the central 1.0 baseline. No release promotion, application-version bump or database migration is implied.

## Question and evidence

How can the new multi-document, native Office, registry and worker features retain the accepted application/security ownership? Review against Studio `6139a144` and OMI `65f25c9`.

The earlier drift report overstated pending-change loss on tab switching: the switch already checkpoints. The verified defect is a singleton native working path, and session ownership/selection/pending recovery outside an application service. A new shared fixture also exposed that removing nested historical image previews can change legacy v1 state digests. Never reinterpret those existing digest bytes.

## Decisions

| Boundary | Decision | Alternatives / reason | Consequence and revisit |
|---|---|---|---|
| Native Office | Opaque iframe origin: HTML `sandbox` and response CSP `sandbox allow-scripts allow-downloads`, no same-origin/forms/popups. Host network policy permits only configured Office origin, no API self connection. Parent checks opaque origin, exact window and random channel; only launch config is passed. | Same-origin sandbox permits remote DocsAPI to inherit API authority. A separate cookieless host remains valid but would require additional operator infrastructure. | No native IPC, parent DOM or origin storage; reject forged messages. Real Office Windows/Android storage/download/save/reopen acceptance blocks promotion. Revisit provider incompatibility; never restore `allow-same-origin` on the API origin. |
| Document sessions | Framework-independent `createDocumentSessionManager` owns sessions; Zustand is active-session adapter and React observes snapshots. Preserve pending batch and selection/proofing state before external opens. Keep checkpoint-on-switch and revision engine. | Replacing Zustand/Tiptap/history unnecessary. A React tab containing manuscript alone lacks working-session ownership. | Recovery cache carries runtime session fields, never native paths or portable OMI fields. Existing recovery limitations remain; PM undo/focus is runtime-only, not a new portable guarantee. |
| Native location | Runtime `DocumentFileLocations` keyed by manuscript ID. Save always looks up the manuscript being saved, not the last opened path. Shared-device policy clears all associations; new document no longer clears other documents' locations. | Global path risks writing A to B's file; copying native URIs into OMI leaks platform/private state. | Unbound documents use Save As. No persistence of scoped handles across restart; future handle restoration requires platform validation. |
| Extension registry | Add `/api/v1/integrations/extensions` and discovery, keep `/api` facade, same router/DTO/auth and per-owner service/repository. Do not mount unrelated execution endpoints under v1. | Payload `apiVersion` alone does not version the HTTP API. No mass route rename or plugin runtime. | Manifest registration remains declaration only. API-v1 accepts same strict manifest and no-grant flags; real DB remains separate integration acceptance. |
| Container | Declare `urn:omi:studio:container:asset-previews:1` in the Draft manifest. Recursively normalize **current document** previews; preserve **exact historic snapshots**, including legacy previews/digests. Existing alpha container version and absent-profile legacy packages remain readable; unknown explicit profiles reject before editable import. | Rewriting historic bytes or silently changing v1 canonicalization can invalidate evidence. Incrementing the whole container format is unnecessary for an additive implementation-profile declaration. | Shared synthetic golden package and independent ZIP/checksum inspection in OMI. History may be larger; quotas remain. A later historical preview transformation requires a separately versioned digest/codec and evidence-preserving conversion. |
| PDF process | Production API requires socket, even if `PDF_WORKER_REQUIRED=false`; test/development may use local toolchain. Dedicated systemd worker invokes explicit local executor and never re-dispatches to itself. | Silent production fallback defeats the isolation boundary. Disabling all Studio editing is unnecessary. | Missing socket disables PDF processing only. Units/ACL/resource/network acceptance remains mandatory; no claim that source changes deploy the service. |
| Release | 1.0 guard validates owner evidence for exact source SHA + actual release file hashes, trusted successful same-SHA workflow runs, and mandatory manual gates. Publish prior reviewed native build artifacts instead of rebuilding approved bytes. | Issue closure and structural CI markers are insufficient. An owner's receipt is not independent certification. | Missing/failed/foreign/stale-subject evidence fails before tag creation. Beta path unchanged. Revisit scope/platform/gate changes explicitly. |

## Validation and rollout

Synthetic service/session/native IO tests; v1/legacy HTTP owner and manifest tests; container golden/revision digest test; negative RC subject/gate/hash tests; existing security/build/recovery gates. Browser regression executes the real Office host and tests denied parent/storage/API reads. Actual provider/device/host/manual evidence cannot be manufactured by unit tests.

Deploy matching API before native client. Opaque-host changes require the new native client: historical clients with `allow-same-origin` cannot correctly use the new opaque-origin handshake, so deploy in a controlled tester window and retain a matched secure rollback pair. Never restore blanket native script execution. Production PDF requires the documented socket/service before PDF use. Keep SQL schema and portable OMI unchanged; roll back session/registry adapters independently, preserving user files and recovery snapshots. Release evidence and fixtures contain only public URLs, synthetic content and content-free pass/fail data, never private manuscript titles/paths.
