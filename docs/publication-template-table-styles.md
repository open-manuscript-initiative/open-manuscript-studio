# Table styles in publication templates

In the table appearance panel, select a built-in or locally saved preset, then copy it to the publication. The portable publication style stores a validated presentation-only catalog of up to 50 named presets. Select a publication table preset to apply it to a whole table; select a cell preset to apply it to a cell selection. Publication presets can be removed independently of the local catalog. Set or clear an optional default table style; deleting that preset clears its default reference.

Saving the current publication as a publication template captures the catalog together with the publication style. Exporting/importing that template or reopening its OMI document preserves the snapshot without a dependency on the original browser's local style catalog. Later changes to a different template or the local catalog do not alter existing documents.

The default is materialized when creating an empty table using the Insert element panel or inserting a new nested table. Imported tables, text-to-table conversions and existing unlinked tables are not implicitly restyled. New nested tables also receive the publication default. Applying a preset explicitly replaces its supported appearance properties but leaves text, notes, dimensions, merged geometry and row-break rules unchanged. New blank tables using a publication default and tables explicitly assigned a publication table style now retain a live catalog name. Editing that definition from a representative table updates linked tables in the current publication, including nested section/block trees. Direct cell overrides survive definition changes (border and padding groups are atomic); deleting the definition or detaching a table freezes the materialized appearance. Built-in/local table styles detach the publication link. New rows and columns inherit their region appearance, row moves recompute banding by position, and newly exposed split cells receive the current style. Linked nested tables retain their reference in rich-cell JSON and update even inside unlinked parent tables. No server-side style-library synchronization is introduced. Existing documents without a link are not inferred or retroactively restyled.

The optional tableStyles field is backward compatible. Publisher-profile and applied-template validation reject invalid default references, duplicate names, excessive catalogs, unsupported fields and noncanonical values. Existing format exporters use the materialized cell properties.

Regression tests cover catalog capture, JSON/template validation, OMI reopening, live bindings, direct overrides, row and column growth, positional banding on row moves, nested-table normalization and definition deletion. Actual UI execution and export rendering require CI and device checks.

Named publication cell styles can be linked to any cell selection. They take precedence over table region styles, travel with row and column moves, and remain dormant under merged cells. Updating a cell definition from a representative cell refreshes linked cells while retaining direct differences. Reset selected cells to their linked cell style or table region; detach or delete a cell style to freeze its appearance. A local cell preset removes the selected cell links. Both cell and table links survive nested-table normalization. Direct overrides are inferred from differences to the previous definition, not explicit override flags.

Publication table definitions can derive from another named table definition through multiple levels. Header/body and optional regions are sparse property patches; border and padding groups are atomic. Cycles and missing ancestors are rejected at the portable validation boundary. Deleting a parent flattens its direct children to their resolved definitions so descendants retain their appearance. Use the table style regions panel to create a derived style or capture/clear a region from a selected cell. Header cells take precedence over body regions; body precedence is body/alternate, first column, last column, then summary (last body row), followed by named cell styles and direct formatting. Summary is positional and follows row growth. Legacy alternate formats replace the body rather than layering onto it. A cleared child region inherits its parent; no explicit suppression of a parent's optional region is introduced.

Conditional formatting rules are ordered, limited to 24 per table definition and applied to body cells after regional styles and before named cell styles and direct overrides. Supported predicates are exact text, substring (case-sensitive), empty/nonempty, and numeric comparisons (<, ≤, >, ≥). Numeric operands accept a single decimal comma or point; no grouping, units, formulas or exponent syntax. Later matching rules override earlier fields. Child styles inherit the parent's list unless they define their own (including an explicit empty list). The current UI creates background-color rules; the model supports normalized appearance patches. Values are evaluated during normal table edits and geometry changes; export uses materialized formats. No spreadsheet formula engine is introduced.
