# Open Manuscript Studio 1.0 blocker policy

This policy turns release decisions into reproducible gates. A schedule or a
readiness score cannot override a red mandatory gate.

## Labels

| Label | Meaning | Required action |
| --- | --- | --- |
| `release-blocker` | Known failure that makes the advertised release unsafe or unusable | Must be closed or the affected Stable claim removed |
| `rc-required` | Must be completed before the first release candidate | Must be closed before tagging RC1 |
| `manual-test` | Physical-device, visual, historical-content, or owner acceptance needed | Evidence must be linked from the issue |
| `automation` | Reproducible automated implementation or verification task | CI or a committed report must prove completion |
| `external-dependency` | Completion depends on an upstream project, store, certificate, or external approval | Document the owner, review date, and fallback |

## Mandatory red gates

Any reproducible failure in the following categories is a `release-blocker` for
a Stable target:

1. manuscript text, note, image, table, citation, index anchor, or identifier is
   lost, duplicated, silently moved, or attached to the wrong object;
2. an unauthorized user can read or change a manuscript, identity, review,
   credential, or sibling document;
3. blind-review identities leak, or review rounds/assignments are mixed;
4. a supported upgrade, migration, save, restore, or rollback makes a document
   unreadable or loses the last confirmed state;
5. a Stable installer cannot be installed, launched, updated, or removed on its
   declared reference platform;
6. a critical workflow cannot be completed with keyboard input or the declared
   Android accessibility path;
7. an unmitigated Critical or High security finding has a reachable project
   path.

## Severity and response

| Severity | Example | Release rule |
| --- | --- | --- |
| P0 | Active security exposure or repeatable data loss | Stop deployment; fix immediately; add regression test |
| P1 | Stable critical path blocked, crash/OOM on reference data, anonymity failure | Blocks beta/RC promotion until fixed |
| P2 | Degraded non-critical workflow with a safe workaround | May ship only when documented and explicitly accepted |
| P3 | Cosmetic or low-impact improvement | Post-1.0 unless bundled with a necessary fix |

Every P0/P1 fix needs a reproduction, an automated regression test where
technically possible, and a short statement of the preserved invariant.

## External dependency exception

An upstream-only warning may remain open for 1.0 only when all of the following
are recorded:

- there is no compatible fixed release;
- no reachable application path is known;
- available mitigations are enabled;
- the issue has an owner and review date;
- the public support statement does not conceal the limitation.

The existing Tauri/GTK `glib` advisory is handled through this process; it is
not silently marked resolved.
