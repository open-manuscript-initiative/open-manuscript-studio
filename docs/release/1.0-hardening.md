# Open Manuscript Studio 1.0 release hardening gate

Status: Route A release gate
Target: v1.0.0
Scope: security, accessibility, recovery, updates and installers

## Purpose

This gate turns the existing production code paths into repeatable release
evidence. It does not add a new application subsystem. A green result means the
covered invariants were exercised on the exact source commit; it is not a claim
that every possible operating-system, assistive-technology or failure scenario
has been certified.

## Security

The automated gate verifies that:

- portable OMI manuscripts reject credential-like fields such as passwords,
  access/refresh/session tokens, client secrets and private keys even when they
  are nested in extension data;
- central OMI Identity cannot silently create or merge an existing local
  account;
- native ORCID handoff accepts only registered return origins and keeps the
  one-time handoff code out of the query string;
- OJS/OMP and cloud integrations retain their declared authentication
  boundaries;
- website artifacts cannot claim `peer-reviewed` without a complete
  Studio-native review round, an editor decision bound to the exact committed
  revision, matching visible/machine-readable assurance and server-side
  evidence validation; reviewer identity never enters the public evidence;
- the desktop updater requires a build-time public key and uses the fixed HTTPS
  GitHub release metadata endpoint;
- the integration-test SSRF host exception remains available only under
  NODE_ENV=test.

CodeQL and the existing PKP/OJS authorization tests remain complementary gates;
this document does not replace them.

## Accessibility

Playwright runs a release accessibility contract on desktop Chromium and a
Pixel-class mobile Chromium viewport.

The browser checks require:

- a visible level-one login heading and main landmark;
- labelled form fields and accessible names for visible interactive controls;
- accessible names for visible dialogs;
- alt attributes on visible images, including deliberately empty alt text for
  decorative images;
- no duplicate DOM IDs;
- no positive tabindex values;
- keyboard-only traversal through the local login form; and
- keyboard opening plus Escape closing of the manuscript dialog.

This is a regression gate for the Studio UI, not a complete WCAG certification.
Screen-reader, high-contrast and platform assistive-technology sessions remain
valid manual acceptance work when release evidence requires them.

## Recovery

Two layers are exercised:

1. unit tests preserve working-state checkpoint semantics and prove that a late
   IndexedDB restore cannot overwrite a newer OJS import;
2. a real browser round trip creates and edits a manuscript, waits for the
   debounced IndexedDB session snapshot, reloads the application without
   closing the document, and requires the edited manuscript to return.

Explicit document close remains authoritative and is intentionally different
from crash/session recovery.

## Update paths

The update gate verifies:

- Play-distributed Android builds always route updates through Google Play;
- direct Android builds require a release SHA-256 digest before native APK
  installation;
- desktop native updater metadata takes precedence over public-download
  fallback and calls the Tauri updater installation path;
- when signed desktop updater metadata is unavailable, the application falls
  back to the immutable platform release asset rather than inventing an update
  destination.

## Installer round trips

The existing Tauri multi-platform workflow is the package-level release gate.

### Windows 11 x86-64

The workflow builds both MSI and NSIS bundles. It silently installs the MSI,
requires a successful Windows Installer result, then silently uninstalls the
same MSI and requires success. The NSIS setup executable must also be present
and non-empty.

### Ubuntu 22.04/24.04 x86-64

The workflow validates the DEB metadata, installs the generated package with
dpkg, verifies the installed package database and file list, removes the
package, and confirms that it is no longer installed. The AppImage is also
extracted without FUSE and must contain an executable AppRun entry point.

### Android 10+

The workflow validates the generated APK with Android build tools, requires the
package id org.openmanuscript.studio, the configured minimum SDK, and a valid
APK signature.

A physical-device install/update/uninstall session is still required on the
recorded reference Android device before RC/1.0 sign-off. CI package inspection
does not pretend to replace OEM-specific package-manager behavior.

## Evidence

The 1.0 Readiness workflow runs the security, recovery, update and browser
accessibility gates and writes:

`benchmark-results/release-hardening.json`

The Tauri workflow provides the cross-platform installer evidence. A release
candidate is not considered hardened if the readiness workflow is green but a
Stable-platform installer job is red.

## Release rule

Security, data-recovery, accessibility regressions that block ordinary keyboard
use, failed update integrity checks, or failed Windows/Linux installer
round-trips are Route A release blockers.

Android package CI must be green, and the reference-device manual round trip
must be recorded before final RC/1.0 approval.
