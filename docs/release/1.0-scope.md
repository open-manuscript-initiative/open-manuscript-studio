# Open Manuscript Studio 1.0 support scope

- Status: accepted route, remaining hardware target pending
- Decision date: 2026-09-10
- Baseline: `v0.1.0-beta.6`

## Release route

Version 1.0 follows **Route A: focused stable release**.

| Area | 1.0 status | Release consequence |
| --- | --- | --- |
| Web application | Stable | Blocking |
| Windows 11 x86-64 | Stable | Blocking |
| Ubuntu 22.04/24.04 x86-64 | Stable | Blocking |
| Android 10 or newer | Stable | Blocking |
| OJS 3.5.0-4 and 3.5.0-5 | Stable | Blocking |
| OMP 3.5.x | Preview | Non-blocking, but privacy and data-loss failures still block publication |
| macOS packages | Preview | Non-blocking; do not advertise signed/notarized support without evidence |
| iOS/iPadOS | Experimental | Simulator evidence only; no public 1.0 support claim |

The absence of Apple signing, notarization, TestFlight, or physical iOS testing
does not block Route A. Preview and Experimental features must be visibly
separated from Stable features in the application and public documentation.

## Browser target

The web target is the current and immediately previous major release of Chrome
and Edge, plus the current Firefox release. These browsers become Stable only
after their critical-path Playwright jobs are green for the release candidate.
Safari/WebKit remains Preview under Route A.

## Import and export target

The native OMI container is the authoritative Stable save format. DOCX import,
DOCX export, print PDF, and interactive PDF are Stable candidates and must pass
the semantic round-trip and visual acceptance gates before RC1. HTML, JATS,
EPUB, IDML, and other DTP-oriented outputs retain Preview or Experimental
status until the conformance matrix records evidence for every mandatory
element.

No format may be described as Stable merely because an export button exists.
Unsupported Word constructs must produce a specific warning and a documented
workaround rather than disappearing silently.

## Feature freeze

From the first `1.0-rc` tag until `v1.0.0`, changes are limited to:

- release-blocking data integrity, authorization, anonymity, migration,
  installation, or accessibility fixes;
- regressions with a reproducible test;
- translation corrections and documentation that do not change behavior.

New editing features move to the post-1.0 roadmap unless they are required to
remove a release blocker. Reclassifying a failed gate to preserve a date is not
permitted.

## Private manuscript rule

Real manuscripts used for acceptance testing stay outside Git and outside CI
artifacts. Benchmark output may contain only counts, timings, memory values,
content digests, and an explicitly supplied non-sensitive label. File paths,
titles, author names, document text, note text, images, and extracted metadata
must not be emitted by the benchmark harness.

The reference manuscript for the first baseline is the privately supplied
large Hungarian DOCX. It is never copied into this repository.

## Provisional schedule

The working four-week release window is **2026-11-09 through 2026-12-06**. It
is provisional until the owner approves the reference-device measurements.
The date never overrides a mandatory gate.

## Pending owner inputs

- Reference Windows or Linux laptop model, operating system, CPU, and RAM.
- Reference Android device model, Android version, and RAM.
- Final approval of the provisional four-week release window.
- Approval of branch-protection changes after the new readiness workflow is
  proven green.

## Exit gate

This scope is complete when every 1.0 work item is mapped to an owner and a
release gate, the reference devices are recorded, and no required behavior is
left implicit.
