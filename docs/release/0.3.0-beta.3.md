# Open Manuscript Studio 0.3.0-beta.3

Status: scholarly authoring, collaboration and publication beta  
Date: 2026-09-29  
Previous release: 0.3.0-beta.2

## Release purpose

This beta consolidates the changes made after the live-collaboration release.
It improves linked Word notes and non-printing marks, adds persistent chat for
accepted collaborators, and makes publication and portable export choices
clearer while preserving the existing output formats and template controls.

## Authoring and Word export

- Anchored OMI notes export as native, linked Word footnotes by default;
  explicitly selected endnotes remain native Word endnotes.
- Word note markers are superscripted and the note body is separated from its
  number. Unanchored notes remain in an appendix with an export warning.
- Non-printing marks display regular and non-breaking spaces, tabs, line breaks
  and paragraph marks without changing document content.

## Collaboration

- Accepted collaborators can use persistent chat scoped to their manuscript.
- The server authorizes message reads and writes using active collaboration
  membership and validates message content.
- Invitation controls and shared-editing actions are localized, including
  cancel and reopen behavior.

## Publication and interchange

- Standard DOCX, semantic HTML5 and PDF are distinct export formats. Print PDF,
  the visual publication editor and its styled HTML web view have separate,
  clear roles.
- Template-based DOCX, PDF and HTML exports retain their ordering, typography,
  citations, localized front matter, note selection, headers, footers and page
  numbering.
- JATS 1.4 output externalizes embedded image payloads into integrity-checked
  package assets when needed, uses compliant figure markup and descriptive link
  text.
- IDML package structure follows InDesign's expected design map and entry order.
- The portable OMI ZIP package is the author-facing interchange package;
  OMI JSON is a single-file option for machine processing and does not bundle
  media assets. Export formats provides the package download, while Tools
  handles asset preparation, integrity checks and verified package opening.

## Architecture and compatibility

These changes do not alter the OMI schema, JSON envelope, `.omi` container
contract or API-v1 contract. Existing OMI-SPEC-320@0.2.0 manuscripts need no
migration. The new package-menu workflow retains asset externalization,
revision digests, integrity checks and verified opening.

## Release gates

Before publication require green results for OMI Studio CI/CD, 1.0 Readiness,
CodeQL, PKP integration acceptance, Tauri desktop/mobile builds and the iOS
simulator smoke build. Android Play publication remains a separate explicit
Android Release workflow action.
